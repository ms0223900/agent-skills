# 測試價值把關（Test Value Gate）

一支測試要值回維護成本：它保護一個可觀察行為、一個可信的回歸，或一個獨立有意義的契約。本檔是撰寫新測試（把關）與稽核既有測試（`/test-audit`）共用的同一把尺。

## 把關四題

新增或修改任何測試前，逐題寫出具體答案；任一題答不出來，就先不要加這支測試：

1. **保護什麼？** 哪個可觀察行為、不變式或獨立契約（能對應到哪條 AC 或哪個公開介面）。
2. **哪個回歸會讓它變紅？** 說出一個可信的錯誤改動（條件寫反、欄位漏傳、排序顛倒）。綠燈後的 mutation test 就是在實證這一題。
3. **為什麼現有測試抓不到？** 每個契約在**最強邊界**只有一個主要擁有者（owner）；其他層要加測試，必須有 owner 碰不到的獨立風險（例如跨頁導航、網路傳輸、生命週期）。能擴充既有 `it.each`／table-driven case 或共用 fixture，就不要新增近似重複的測試；同一次改動裡順手合併重複的 setup。
4. **需要只為測試存在的 production 接縫嗎？** 例如為了測試才 `export` 的內部 helper、測試專用 flag／global、只為注入而加的參數、斷言 `wrapper.vm` 上的內部方法。需要 → 改到真實邊界去測。

接著逐條對照下方[垃圾測試清單](#垃圾測試清單)。命中任一條即不通過，除非能用[保留標準](#保留標準)說出它獨立守護的契約。

試金石：**行為不變的重構**（改名、拆函式、調整內部順序，輸入輸出不變）會讓它壞掉的測試，是在斷言實作而非行為——落地前先改到 owner 邊界重寫。

## 回歸測試

- 回歸測試必須在**修正前的程式**上因為**該 bug** 而紅，修正後轉綠。從沒實證紅過的回歸測試，證明的是 mock，不是修法。
- 實證方式：先寫測試並跑出紅燈（紅的原因要對上 bug 的症狀），再套用修正跑到綠；或修正後暫時還原修正（`git stash` 產品碼）確認轉紅，再恢復。
- 一個 bug 在 owner 邊界寫**一支**回歸測試即可，不要在它經過的每一層各重演一次。

## 垃圾測試清單

- **無斷言的覆蓋率探針**：只 render／呼叫、沒有 `expect`，或只斷言剛建立的東西 `toBeDefined()`／`toBeTruthy()`。
- **自我比較與原樣複製**：`expect(fn(x)).toEqual(fn(x))`、把輸入原封不動當期望值。
- **抄一份清單來比對**：逐項抄寫常數表、路由表、i18n key、export 列表、設定檔內容再斷言相等。
- **原始碼／import／字串 grep**：讀檔案內容斷言含某字串或某個 import。
- **私有判斷或呼叫形狀**：斷言內部 helper 被 `toHaveBeenCalledWith(...)` 某組參數，而真實邊界已有測試涵蓋同一結果。
- **同一契約重複測**：多個 `it` 只換名字、實際走同一條路徑；或同一條 AC 在 unit、integration、E2E 各測一次卻沒有各自的獨立風險。
- **只為保住測試專用 export／global／wrapper 而存在的測試**。
- **只剩測試在呼叫的 production 死碼**。
- **期望值由受測對象產生**：用受測函式、同一個 formatter 或同一個 renderer 算出期望值。
- **mock 自己實作了要驗的行為**：mock getter／API 直接回傳算好的結果，再斷言畫面顯示該結果；或同一個 mock 同時頂替多個不同 API。
- **fixture 先替受測流程把結果做好**：fixture 預填了本該由受測流程寫入的 store 狀態、回呼順序或回執；或斷言一個該流程根本不會寫入的 store／storage。
- **只重述宣告的 flag／設定**：斷言 feature flag 或 config 的值本身，而不是驗證這個 flag 承諾的行為真的發生。
- **反向測試因無關原因而過**：期望的錯誤其實來自另一道驗證、缺漏的 mock 拋錯或型別錯，而不是受測的那條防線。
- **名稱或 fixture 承諾的比實際測到的多**：叫「結帳後清空購物車」卻只斷言按鈕存在。
- **大型 snapshot 當唯一斷言**：沒人審視過內容、改版就 `-u` 更新的快照。

## 保留標準

以下情況即使看起來像實作細節，仍應保留，除非已證明有更強的 owner 測試守著同一件事：

- 獨立守護**公開契約**：元件 props／emit／slot 介面、公開 API、URL 與路由、設定與預設值、storage key 與資料格式、資料遷移、安全與權限、使用者可見的文案或 i18n key、analytics 事件 payload、跨端或產生出來的契約、套件匯出。
- **呼叫順序本身就是可觀察行為**時的順序斷言。
- 有**可信失敗模式**的回歸測試。
- **原始碼檢查是最便宜的獨立防線**時：契約改變（使用者看得到的 key、字串、路徑）它就紅，只改識別字名稱它不受影響。
- 在 baseline 上就**紅的**保留測試：先當成可能的產品 bug 重現並修 owner，不要直接刪。

「靜態」或「跑得慢」都不是刪除理由。
